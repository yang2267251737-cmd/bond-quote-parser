# 债券报价文本结构化工具

使用 Python 将格式不固定的报价文字转成可筛选、可追溯的 CSV / JSON，辅助人工整理和复核。本项目是本地原型，未接入交易系统或大模型，不执行交易。

**仓库中的债券代码、简称、机构、联系人、联系标识、价格和交易代码均为虚构测试数据。真实业务输入、生成结果和本地备份不随仓库发布。**

## 处理流程

```text
文本输入 → 全半角与标点标准化 → 债券代码分笔 → 规则提取
        → 机构别名归一 → 缺失和冲突检查 → CSV / JSON → 人工复核
```

- 不依赖固定空行，支持空格、制表符、全角字符及部分换行变化。
- 提取代码、简称、金额、价格、价格类型、收益率、to 两端机构、请求发、先手、联系人和交易代码。
- 用 Decimal 保留价格精度，代码和账号按字符串保存，保留前导零。
- 保留原文、行号、字段依据、运行配置和未分配数字。
- 完全重复的文本只作标记，不自动删除；同券的不同报价分别保留。
- 缺失字段不从邻近联系人或其他报价中补写。

## 运行

需要 Python 3.10 或以上版本，无第三方依赖。

```powershell
python quote_parser.py examples/demo.txt --out outputs/demo
python -m unittest discover -s tests -v
```

结果为 outputs/demo/quotes.csv 和 outputs/demo/quotes.json，二者都被 Git 忽略。CSV 使用 UTF-8 BOM，可用 Excel 打开。相同输出目录会覆盖旧结果，应按批次指定不同目录。

```python
from quote_parser import load_config, parse_text

sample = "999991.SZ 26演示债甲 120 净价96.4321 示例甲 to 示例乙"
result = parse_text(sample, load_config())
for row in result["records"]:
    print(row["bond_code"], row["amount_wan"], row["quote_price"], row["issues"])
```

## 配置与业务口径

config.json 仅包含虚构机构字典，金额默认万元只是可调整的演示配置。实际运行应使用本地专用配置，且不要提交真实字典或通讯录。

```powershell
python quote_parser.py inputs/my_batch.txt --config config.local.json --out outputs/my_batch
```

| 配置 | 默认值 | 含义 |
|---|---|---|
| default_amount_unit | 万元 | 无标签金额的演示单位，可设 null |
| default_price_type | null | 没有标签时不判断净价/全价 |
| unlabeled_rate_is_yield | false | 中间数字只作为候选，不自动认定收益率 |
| to_means_seller_to_buyer | false | 仅保存 to 两端，不自动映射买卖方 |
| institution_aliases | 虚构别名 | 仅精确匹配，保留产品全称 |
| contact_directory | 空 | 仅在核实后按联系标识关联机构 |

配置应按渠道和模板分别管理，不应把单一渠道的含义扩展到所有报价。

## 虚构示例

演示文件包含四笔人工编写的测试报价，不能用于市场研究或交易。

| 虚构代码 | 虚构简称 | 演示金额（万元） | 演示价格 | 特征 |
|---|---|---:|---:|---|
| 999991.SZ | 26演示债甲 | 120 | 96.4321 | 显式净价、右端缺失、补充交易代码 |
| 999999991.IB | 26演示MTN甲 | 250 | 101.5678 | 中间数字、机构别名、未注明所属机构的联系人 |
| 999999992.IB | 26演示MTN乙 | 80 | 103.2468 | 产品名称包含数字、箭头方向 |
| 999999992.IB | 26演示MTN乙 | 80 | 103.2499 | 同券不同报价，不自动去重 |

样例中的无标签数字 2.75 保存为候选，不直接认定为已确认收益率。extraction_status 仅表示提取问题，不表示业务确认或交易许可。

## 输出结构

JSON 数值采用十进制字符串，缺失采用 null。每笔记录包括：

- 债券代码、简称、金额原值及单位、换算面额、价格、价格类型和收益率候选。
- to 左右端的原始名称及标准名称、请求发、先手和可配置的买卖方向。
- 联系人列表及交易代码列表。
- 原始文本、起止行号、字段识别依据、原文指纹、重复记录指向和复核原因。

CSV 是供人工查看的视图。原文中的公式起始字符会进行 CSV 转义，JSON 保留原始内容。JSON 中含有原文和联系人，因此所有生成结果均视为本地业务文件，不应上传。

## 测试与限制

测试全部使用虚构数据，覆盖字段精度、缺失方向端点、金额单位、前导零、标签换序、机构别名、产品数字、重复文本、原文保留和 CSV 转义。测试通过不能代替真实业务验收。

- 当前支持六位或九位 .IB/.SZ/.SH 代码，仅做形态识别，不核验证券主数据。
- 简称通常是代码后的首个文本词。无标签数字按“金额、可选候选收益率、价格”的模板解释；显式标签可以换序。
- 主报价和联系人通常分行。多种字段、聊天时间、联系人混在同一行时可能需要人工复核。
- 联系人目前支持中文姓名加连续数字联系标识，不推断账号类型。
- 未结构化解析清算速度、结算日期、撤单改价、含权收益率口径和图片 OCR。
- 自由文字的边界识别与异常提示不能保证发现所有错误，应在独立标注集上核验。

## 后续实现

1. 增加分渠道模板、证券主数据和人工核实的本地机构字典。
2. 用 Streamlit 实现粘贴后自动预览，原文与结构化结果并排复核。
3. 对疑难记录接入获准模型接口或内网模型，要求 JSON 结构和逐字段原文证据，再进行规则校验。
4. 保存修正前后内容、修改人和时间，使用 SQLite 管理消息、报价、联系人及复核记录。
5. 通过获准的数据入口或本地输入目录触发解析，避免重复入库。

验收时应统计分笔查全率/查准率、关键字段准确率、整行完全正确率和人工复核耗时，不能把全部标记待核当成准确识别。
