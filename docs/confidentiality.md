# 发布与保密约定

## 可发布内容

程序、通用使用说明、虚构机构字典、人工编写的演示文本和使用虚构数据的测试。首版只提交发布清单内的文件。

## 本地资料

真实报价、联系人、交易账号、机构对应关系、实际成交信息、生成的 CSV/JSON/Excel、预览图片、日志、压缩包和原始文档备份只保存在本地。配置中的机构字典和通讯录也属于业务数据，不直接提交。

`.gitignore` 排除输入输出目录、本地配置、备份、图片、表格和压缩包。examples 目录只允许虚构的 demo.txt。使用真实数据时，应指定被忽略的输入目录和 config.local.json。

## 提交前流程

1. 逐个审阅源代码、README、配置及测试，确认没有真实资料或由真实资料改写的完整交易样例。
2. 明确指定文件暂存，不使用强制添加。
3. 运行测试和 `python scripts/check_release.py`。
4. 审阅暂存差异及所有待发布历史。仅删除工作区文件或添加忽略规则，不能移除历史提交中的内容。
5. 检查实际上传的文件清单，上传后核验远端。

## 发布清单检查的作用

检查器只允许既定文件，并要求演示配置为空通讯录、虚构机构别名，README 明确说明样例是虚构数据。它不包含任何真实秘密作为内嵌黑名单，也不能判断任意新内容是否属于机密。新增文件须先人工审阅，再更新清单。

## 历史与压缩包

首个 Git 提交只包含已经审阅的虚构版本，本地原始资料不进入 Git 对象。含真实资料的压缩包不能作为 GitHub 附件或 Release 上传。发布包只能从已审阅的 Git 提交导出。

若未来发生误提交，应先确认哪些引用或远端已经收到内容，按实际影响处理历史、缓存和凭据。不能把当前目录“已删除”视为历史中“从未出现”。
